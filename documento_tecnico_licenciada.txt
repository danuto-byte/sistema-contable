chibi Contable

1. DESCRIPCIÓN GENERAL
Este proyecto corresponde a una aplicación contable de escritorio desarrollada con Electron, integrada con un backend local en Node.js y Express, y una base de datos SQLite. La solución está pensada para uso local en un equipo, con almacenamiento persistente en la carpeta de datos del usuario, sin requerir un servidor externo.

La aplicación permite:
- registrar cuentas contables,
- registrar asientos contables,
- validar la partida doble,
- consultar el libro diario y libro mayor,
- calcular balance general y estado de resultados,
- respaldar y restaurar la base de datos,
- empaquetarse como instalador de Windows.

2. TECNOLOGÍAS UTILIZADAS
- Frontend: JavaScript + Vue 3
- Backend: Node.js + Express
- Base de datos: SQLite con better-sqlite3
- Aplicación desktop: Electron
- Empaque: electron-builder
- Pruebas: Node test runner

3. ARQUITECTURA
La aplicación está dividida en cuatro capas principales:

3.1 Frontend
Ubicación: src/app.js, src/estilos.css, index.html

Responsabilidad:
- mostrar la interfaz de usuario,
- permitir la navegación entre módulos,
- gestionar formularios contables,
- visualizar reportes y saldos,
- presentar la información y los mensajes del sistema.

3.2 Backend
Ubicación: server/index.js

Responsabilidad:
- exponer endpoints HTTP,
- validar datos de entrada,
- ejecutar reglas contables,
- responder con JSON,
- operar con la base de datos SQLite.

3.3 Base de datos
Ubicación: server/db/sqlite.js

Responsabilidad:
- inicializar las tablas,
- sembrar el catálogo contable base,
- guardar cuentas y asientos,
- garantizar la integridad de los movimientos contables,
- respaldar y restaurar la base de datos.

3.4 Electron
Ubicación: electron/main.js

Responsabilidad:
- crear la ventana principal,
- iniciar el backend local dentro de la aplicación,
- abrir la interfaz en localhost,
- mantener el servicio disponible durante la sesión del escritorio.

  - haber

6. REGLAS CONTABLES IMPLEMENTADAS
La aplicación valida lo siguiente:
- cada asiento debe estar balanceado,
- la suma del debe debe ser igual a la suma del haber,
- una línea no puede contener valores a la vez en debe y haber,
- no se aceptan importes negativos,
- cada asiento debe requerir al menos dos cuentas con movimiento,
- la clasificación económica se deriva del primer dígito de la cuenta,
- los saldos se calculan automáticamente por naturaleza contable.

9. BASE DE DATOS Y PERSISTENCIA
La base de datos se almacena localmente en el equipo del usuario. En la versión empaquetada, la ruta suele ser:

%APPDATA%\Sistema Contable\data\sistema_contable.db

Esto permite que la aplicación funcione sin compartir datos en un servidor central ni requerir una instalación de Node.js en la máquina del cliente final.

10. EMPAQUETADO
El proyecto incluye configuración de Electron Builder para generar un instalador de Windows.

Comando:
